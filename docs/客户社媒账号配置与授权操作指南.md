# 灵枢：客户社媒账号配置与授权操作指南

> 适用环境：`https://app.lingshu.site/` 生产环境。本文按当前应用逻辑编写，供灵枢管理员、交付顾问和客户管理员共同使用。

## 1. 先确定使用哪一种配置方式

### 方式 A：使用灵枢统一平台应用（推荐）

由灵枢管理员统一配置 Google、Meta、TikTok 的开发者应用。每个客户只授权自己的社媒账号，客户的 Token、账号、内容和发布记录仍按租户隔离。

适合绝大多数客户。客户不需要自己创建开发者应用，也不需要把 App Secret 发给顾问。

### 方式 B：客户使用自己的开发者应用

仅在客户明确要求应用所有权归自己、已有经过审核的平台应用，或合同要求独立 App 时使用。

此时在“客户运维”对应客户卡片里填写该客户自己的 App ID / Client ID 和 Secret。租户级凭证填写后，会优先于灵枢统一平台应用。

## 2. 角色与入口

| 角色 | 登录入口 | 应进入的位置 | 负责事项 |
| --- | --- | --- | --- |
| 灵枢管理员 | [灵枢工作台](https://app.lingshu.site/) | 左侧“客户运维” | 配平台应用、创建客户、生成协助链接、验收 |
| 客户管理员 | [灵枢工作台](https://app.lingshu.site/) | 左侧“集成中心” | 登录官方平台并确认授权 |
| 客户的 Meta/Google/TikTok 管理员 | 各平台官网 | 官方授权页 | 选择正确主页、频道或专业账号并同意权限 |

## 3. 第一次配置前的准备清单

1. 确认生产域名可正常打开：`https://app.lingshu.site/`。
2. 确认服务器环境变量 `PUBLIC_BASE_URL=https://app.lingshu.site`。
3. 准备一个公司级平台管理员邮箱，不建议使用个人临时邮箱。
4. 为 Google、Meta、TikTok 管理员账号开启双重验证。
5. 准备隐私政策和服务条款公开链接：
   - `https://app.lingshu.site/privacy`（如尚未上线，需先补齐）
   - `https://app.lingshu.site/terms`（如尚未上线，需先补齐）
6. 不要通过微信、邮件或普通表格传递 App Secret、Client Secret、Access Token。

## 4. 灵枢管理员的总配置流程

### 4.1 配置管理员自用及统一平台凭证

1. 打开 [灵枢工作台](https://app.lingshu.site/)并使用管理员账号登录。
2. 左侧进入“客户运维”。
3. 展开顶部“管理员自用账号直连”。
4. 在“平台应用凭证”中填写：
   - YouTube / Google：Client ID、Client Secret。
   - Instagram / Facebook：Meta App ID、App Secret。
   - TikTok：Client Key、Client Secret。
5. 对照界面显示的回调地址，到平台后台逐字填写。
6. 点击“保存平台凭证”。
7. 保存后，管理员交付中心会明文显示 Secret，并在已填写的项目旁显示“填写完成”，便于当场核对。

生产环境当前应使用以下回调地址：

```text
YouTube:
https://app.lingshu.site/api/overseas/youtube/oauth/callback

Instagram:
https://app.lingshu.site/api/overseas/social/oauth/instagram/callback

Facebook:
https://app.lingshu.site/api/overseas/social/oauth/facebook/callback

TikTok:
https://app.lingshu.site/api/overseas/social/oauth/tiktok/callback
```

注意：最终以“客户运维”页面实际显示并可复制的地址为准。Google、Meta、TikTok 后台填写的回调地址必须与页面显示值完全一致，包括 `https`、域名、路径和末尾斜杠。

### 4.2 创建客户空间

1. 在“客户运维”点击“生成注册邀请码”。
2. 填写客户公司名称、联系人、行业和交付备注。
3. 生成邀请码或注册链接。
4. 将注册链接发给客户管理员。
5. 客户完成注册后，系统会创建独立租户空间。
6. 返回“客户运维”刷新，在“正式客户”列表中找到该客户。

### 4.3 使用统一应用时，客户卡片怎么填

如果使用方式 A（推荐）：

- 客户卡片中的 Google、Meta、TikTok Client/App ID / Secret 可留空。
- 系统会自动使用顶部已保存的统一平台应用。
- 顾问只需把状态改为“等客户操作”，然后让客户进入“集成中心”授权。

如果使用方式 B：

- 在客户卡片中录入客户自己的平台 App ID / Secret。
- 保存后检查每个已填项目旁是否显示“填写完成”，并核对 Secret 内容。
- 客户授权时系统会优先使用该客户的独立应用。

## 5. YouTube / Google 配置

### 5.1 Google 后台入口

- [Google Cloud 项目选择器](https://console.cloud.google.com/projectselector2/home/dashboard)
- [启用 YouTube Data API v3](https://console.cloud.google.com/apis/library/youtube.googleapis.com)
- [Google Auth Platform 概览](https://console.cloud.google.com/auth/overview)
- [OAuth 客户端管理](https://console.cloud.google.com/auth/clients)
- [旧版 API 凭证页](https://console.cloud.google.com/apis/credentials)
- [YouTube OAuth 官方说明](https://developers.google.com/youtube/v3/guides/auth/server-side-web-apps)

### 5.2 创建 Google OAuth 应用

1. 在 Google Cloud 创建或选择项目。
2. 启用 `YouTube Data API v3`。
3. 进入 Google Auth Platform，完成品牌信息：应用名、支持邮箱、开发者联系邮箱。
4. Audience：
   - 内部企业 Google Workspace 测试可选 Internal。
   - 要让不同公司的客户授权，应选 External。
5. 测试阶段把客户 Google 邮箱加入 Test users。
6. 创建 OAuth Client，类型选择 `Web application`。
7. Authorized redirect URI 填：

```text
https://app.lingshu.site/api/overseas/youtube/oauth/callback
```

8. 创建后立即复制 Client ID 和 Client Secret。
9. 回到灵枢“客户运维 → 管理员自用账号直连 → YouTube / Google”填写并保存。

当前应用会请求：

```text
https://www.googleapis.com/auth/youtube.upload
https://www.googleapis.com/auth/youtube.readonly
https://www.googleapis.com/auth/youtube.force-ssl
```

### 5.3 客户授权 YouTube

1. 客户使用拥有目标 YouTube 频道权限的 Google 账号登录灵枢。
2. 进入“集成中心”。
3. 找到 YouTube 卡片，点击“去确认授权”。
4. 在 Google 页面选择正确账号。
5. 核对应用名称及权限，点击允许。
6. 返回灵枢后刷新状态。
7. 成功标准：YouTube 显示“已连接”，并能读取频道名称、频道 ID 和视频数据。

如果出现 `redirect_uri_mismatch`，重新复制灵枢页面显示的回调地址到 Google OAuth Client；不要手打。

## 6. Facebook / Instagram 配置

### 6.1 Meta 后台入口

- [Meta for Developers 应用列表](https://developers.facebook.com/apps/)
- [Meta Business Settings](https://business.facebook.com/settings/)
- [Meta Business Suite](https://business.facebook.com/)
- [Graph API Explorer](https://developers.facebook.com/tools/explorer/)
- [Access Token Debugger](https://developers.facebook.com/tools/debug/accesstoken/)
- [Facebook Page 与 Instagram 绑定说明](https://www.facebook.com/help/1148909221857370)
- [Instagram API 官方 Postman 文档](https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api)

### 6.2 账号资产前置条件

Facebook 发布需要客户拥有或可管理的 Facebook Page，不支持把内容发布到个人主页。

Instagram 发布需要：

1. Instagram 已切换为专业账号（Business 或 Creator）。
2. Instagram 专业账号已绑定一个 Facebook Page。
3. 执行授权的 Facebook 用户对该 Page 有足够管理权限。

检查路径：Facebook 切换到目标 Page → Settings & privacy → Settings → Permissions → Linked accounts → Instagram。

### 6.3 创建 Meta 应用

1. 打开 Meta for Developers 应用列表。
2. 创建一个用于企业业务管理的应用。
3. 填写应用域名：`lingshu.site`。
4. 填写隐私政策和服务条款 URL。
5. 添加 Facebook Login / Facebook Login for Business，以及 Instagram API 所需产品。
6. 在 OAuth Valid Redirect URIs 中分别加入：

```text
https://app.lingshu.site/api/overseas/social/oauth/facebook/callback
https://app.lingshu.site/api/overseas/social/oauth/instagram/callback
```

7. 在灵枢“客户运维 → 管理员自用账号直连 → Instagram / Facebook”填写 App ID、App Secret 并保存。

当前应用会请求以下权限：

```text
pages_show_list
pages_manage_metadata
pages_read_engagement
pages_manage_posts
pages_read_user_content
business_management
instagram_basic
instagram_content_publish
instagram_manage_comments
```

开发模式仅应用角色和测试账号可正常授权；对普通客户开放前，需要按 Meta 要求完成 Business Verification、App Review 和相应权限的 Advanced Access。

### 6.4 FB/IG 资产字段是否必填

不是必填。

- `Facebook Page ID（可选）`：OAuth 会自动读取客户可管理的 Page。
- `Instagram User ID（可选）`：OAuth 会从 Page 自动读取已绑定的 IG 专业账号。
- 只有客户有多个 Page/IG，需要固定到某个目标资产时才填写。
- 两个字段都只能填写纯数字 ID，不能填邮箱、用户名或主页链接。

### 6.5 客户授权 Facebook

1. 客户进入灵枢“集成中心”。
2. 找到 Facebook，点击“去确认授权”。
3. 使用管理目标 Page 的 Facebook 账号登录。
4. 在 Meta 授权页选择“编辑访问权限”。
5. 勾选目标 Facebook Page，并同意页面读取和内容发布权限。
6. 返回灵枢并刷新。
7. 成功标准：显示目标 Page 名称、Page ID，状态为“已连接”。

### 6.6 客户授权 Instagram

1. 先确认 Instagram 是专业账号且已绑定 Facebook Page。
2. 客户进入灵枢“集成中心”。
3. 找到 Instagram，点击“去确认授权”。
4. 使用管理已绑定 Page 的 Facebook 账号登录。
5. 在“编辑访问权限”中勾选正确 Page。
6. 返回灵枢并刷新。
7. 成功标准：显示 IG 用户名、数字 Instagram User ID 和对应的 Facebook Page。

如果只返回 Page、没有 IG：先在 Facebook Page 的 Linked accounts 中绑定 IG 专业账号，再移除旧 Business Integration 并重新授权。

## 7. WhatsApp Business 配置

### 7.1 官方入口

- [Meta for Developers 应用列表](https://developers.facebook.com/apps/)
- [Meta Business Settings](https://business.facebook.com/settings/)
- [WhatsApp Manager](https://business.facebook.com/wa/manage/)
- [Meta Embedded Signup API 文档](https://www.postman.com/meta/whatsapp-business-platform/documentation/du6gzjv/embedded-signup)

### 7.2 灵枢客户卡片需要填写

在“客户运维 → 客户卡片 → Meta / WhatsApp”中：

| 字段 | 是否必填 | 来源 |
| --- | --- | --- |
| App ID | 使用客户独立 Meta App 时必填 | Meta App Dashboard |
| App Secret | 使用客户独立 Meta App 时必填 | App settings → Basic |
| Embedded Signup Config ID | 使用 Embedded Signup 时必填 | WhatsApp → Embedded Signup 配置 |
| WABA ID | 接入后必填 | WhatsApp Manager / Embedded Signup 返回 |
| Phone Number ID | 必填 | WhatsApp Manager 号码详情 |
| WhatsApp 真实手机号 | 建议填写 | 带国家码，不含 `+` 和空格 |
| Access Token | 手工接入时必填 | System User 或临时 Token |
| Facebook Page ID | 可选 | 与 WhatsApp 接入无关 |
| Instagram User ID | 可选 | 与 WhatsApp 接入无关 |

### 7.3 Webhook 配置

1. 在客户 Meta 卡片打开“Webhook 回调”。
2. 复制页面生成的 Webhook URL；地址中包含客户租户 ID，不要复用其他客户地址。
3. 复制 Verify Token。
4. 到 Meta App → Webhooks / WhatsApp Configuration 填入 Callback URL 和 Verify Token。
5. 验证成功后订阅 `messages` 和 `message_status`。
6. 回灵枢勾选对应验收项并执行 Webhook 自检。

Webhook 形式如下，必须使用页面实际生成值：

```text
https://app.lingshu.site/api/webhooks/meta/{客户tenantId}
```

### 7.4 客户完成 WhatsApp Embedded Signup

1. 管理员将客户状态改为“等客户操作”。
2. 客户进入“集成中心”。
3. 点击“连接 WhatsApp”。
4. 在 Meta 弹窗中选择或创建 Business Portfolio、WABA 和手机号。
5. 完成短信/语音验证码。
6. 返回灵枢，系统自动保存 WABA ID、Phone Number ID 和授权状态。
7. 用另一台手机给该 WhatsApp 号码发测试消息。
8. 在“我的客户”确认消息进入，并测试回复。

## 8. TikTok 配置

### 8.1 官方入口

- [TikTok for Developers](https://developers.tiktok.com/)
- [Manage Apps](https://developers.tiktok.com/apps/)
- [创建应用官方说明](https://developers.tiktok.com/doc/getting-started-create-an-app)
- [Login Kit for Web](https://developers.tiktok.com/doc/login-kit-web)
- [Content Posting API](https://developers.tiktok.com/products/content-posting-api)
- [App Review Guidelines](https://developers.tiktok.com/doc/app-review-guidelines)

### 8.2 创建 TikTok 应用

1. 注册 TikTok Developer 账号并创建/加入 Organization。
2. 在 Manage Apps 点击 Connect an app。
3. 添加 Web 平台，网站填写 `https://app.lingshu.site/`。
4. 添加 Login Kit 和 Content Posting API。
5. Login Kit Redirect URI 填：

```text
https://app.lingshu.site/api/overseas/social/oauth/tiktok/callback
```

6. 申请以下 scopes：

```text
user.info.basic
user.info.profile
user.info.stats
video.list
video.publish
```

7. 完成 URL ownership 验证、隐私政策、服务条款、应用说明和演示视频。
8. 提交 App Review。
9. 回到灵枢“客户运维”，展开目标客户的 TikTok 卡片。
10. 在“TikTok 应用”填写 Client Key、Client Secret 并保存。
11. 在“回调地址”复制 Redirect URI 到 TikTok 开发者后台，保存后勾选“回调地址已添加并保存”。
12. 点击“TikTok OAuth”自检；需要客户操作时，生成协助链接发给客户完成授权。

TikTok 授权入口始终保持可连接状态；Direct Post 的实际发布能力仍以 TikTok 平台返回的权限为准。

### 8.3 客户授权 TikTok

1. 客户进入“集成中心”。
2. 点击 TikTok 授权按钮。
3. 登录要发布内容的 TikTok 账号。
4. 同意资料读取、视频列表和发布权限。
5. 返回灵枢并刷新。
6. 成功标准：显示 TikTok 昵称/Open ID，状态为“已连接”。

## 9. 给客户生成协助链接

适用于不方便让客户进入技术配置页、只需要客户完成官方授权的场景。

1. 管理员进入“客户运维”。
2. 展开目标客户的平台卡片。
3. 点击“生成协助链接”。
4. 系统自动复制链接，链接默认 24 小时有效且只能完成对应租户授权。
5. 将链接发给客户的官方账号管理员。
6. 客户打开链接并点击开始授权。
7. 授权完成后链接会显示完成状态；管理员回“客户运维”刷新验收。

协助链接是动态生成的，不要手写或长期复用。

## 10. 验收清单

### YouTube

- 能读取频道名称、频道 ID、视频数量。
- 能上传一条仅自己可见/不公开测试视频。
- Token 刷新后仍可读取频道。

### Facebook

- 能读取目标 Page。
- 能读取页面内容和评论。
- 能发布一条测试视频并得到真实帖子链接。

### Instagram

- 能识别 IG 专业账号及其绑定 Page。
- 能读取媒体列表和评论。
- 能发布测试 Reel 并得到真实媒体链接。

### WhatsApp

- 客户发送消息后 30 秒内进入“我的客户”。
- 灵枢发出的测试回复能到达客户手机。
- Webhook 已订阅 `messages` / `message_status`。

### TikTok

- 能读取账号基本信息和公开视频。
- 审核通过后能完成 Direct Post 或草稿上传。

## 11. 常见故障

### “去确认授权”点了没反应

1. 刷新灵枢页面后重试。
2. 允许 `lingshu.site` 打开弹窗。
3. 确认管理员已经保存对应平台的 Client ID / Secret。
4. 检查平台后台回调地址与灵枢显示值完全一致。
5. 如果弹窗被拦截，系统会尝试在当前页面打开授权页。

### YouTube 提示 `redirect_uri_mismatch`

重新复制：

```text
https://app.lingshu.site/api/overseas/youtube/oauth/callback
```

到 Google Auth Platform → Clients → 对应 Web client → Authorized redirect URIs。

### Meta 没有返回 Page

1. 确认登录用户有 Page 的 Facebook access 或 task access。
2. 授权时点“编辑访问权限”并勾选 Page。
3. 到 Facebook Settings → Business Integrations 移除旧授权，再重新连接。

### Meta 返回 Page 但没有 Instagram

1. 确认 IG 是 Business/Creator 专业账号。
2. 确认该 IG 已绑定当前 Page。
3. 确认授权用户能管理该 Page。

### Secret 是否保存成功无法判断

保存后，管理员交付中心会在已填项目旁显示“填写完成”，Secret 输入框保留明文，便于管理员核对。普通客户页面和非管理员接口不会返回平台应用 Secret。

## 12. 安全要求

1. Secret、Token 只在灵枢受控页面中填写。
2. Secret 仅向已登录的管理员在交付中心明文展示，服务器仍加密保存；普通客户页面和非管理员接口不返回明文。
3. 客户 Token 按 `tenantId` 隔离，不得复制到其他客户空间。
4. 离职或交付人员变更时，应撤销其 Meta/Google/TikTok 管理权限。
5. 客户取消合作时，应在灵枢断开账号，并在平台官网撤销 Business Integration / OAuth 授权。
6. 生产环境仅使用 HTTPS 回调地址。
